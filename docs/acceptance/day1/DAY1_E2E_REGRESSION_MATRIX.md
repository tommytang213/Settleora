Status vocabulary:

- `Not run`: validation exists or is planned, but has not been run for this matrix branch.
- `Planned`: coverage target is identified, but executable or manual evidence is not complete.
- `Automated coverage exists`: repo has code/tests or prior QA-map evidence for a bounded slice; this is not a Day 1 pass by itself.
- `Manual evidence required`: maintainer/QA/security/money/storage/deployment evidence is required before acceptance.
- `Blocked`: a Figma/reference, manual gate, implementation gap, or architecture/runtime dependency prevents full E2E acceptance.

## Authority Guardrails For Every Row

- API/domain services own server-mode business writes, authorization, money, status transitions, storage access, sync acceptance, and audit.
- Workers must not mutate core business tables directly.
- Clients may render, cache, and queue, but must not become the source of authorization, financial truth, settlement state, storage access, sync acceptance, or audit truth.
- OpenAPI remains the contract source of truth when contracts are in scope; generated clients are not hand-edited.
- File bytes go through storage abstraction, metadata remains in PostgreSQL, and API responses must not expose storage internals.
- Money uses decimal-safe values with currency attached and centralized rounding.
- OCR output is provisional. OCR parser/provider output must not finalize bills or mutate authoritative money state.
- Audit/logs must avoid secrets, tokens, passwords, raw credentials, recovery codes, raw OCR text, sensitive file contents, storage internals, provider object keys, signed URLs, and unrelated sensitive content.
- Public/admin exposure, deployment, security, storage/privacy, schema, OpenAPI/generated-client, and money/settlement authority gates remain explicit.

## Regression Evidence Rules

- A row can be used for PR evidence only when the exact branch, head SHA, commands, and results are recorded in the task report or PR body.
- A row with `Automated coverage exists` still needs current-branch validation when it is used to support a risky implementation branch.
- A row with `Manual evidence required` remains non-passing until a human records the relevant evidence.
- A row with `Blocked` must name the blocking dependency in the PR/report instead of being converted to `passed`.
- Docs-only validation can prove this matrix is well-formed and discoverable, but it cannot prove runtime, UI, security, storage/privacy, money, settlement, OCR, sync, deployment, or acceptance readiness.
