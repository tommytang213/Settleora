# Receipt OCR description edit and null tax-mode correction

Fresh independent review of clean head `ee044e2c89f154a63bb16fe6826ef3f5378ac31d` found two distinct defects. Codex section 01 found that changing only an OCR item description cleared `adjustmentsComplete` and disabled item and currency Apply for a balanced included-tax draft. Grok section 03 found that a saved review with a legacy null tax mode returned null before comparing edited header evidence, so changed header roles, amounts, currency, additions and removals did not become unresolved.

Pre-fix focused tests reproduced both outcomes on that head: description-only Apply failed in personal and group flows (two failures), and five changed-header null-mode cases returned null instead of unresolved. Same-header null mode remained null, as expected. Logs and the exact source/test bindings are preserved in the local description-and-null-mode evidence directory.

The editable form still compares descriptions exactly when synchronizing its controllers. For financial evidence invalidation only, it now ignores description text while comparing item count, quantity, unit price, line total, currency and currency ownership. The corrected description is copied into the draft. An empty description, invalid or overprecision money, and a real amount change still block Apply. The existing warning regression now checks that a description correction keeps the warning absent while a real line-total change restores it. The saved-review tax-mode function now compares header evidence before retaining a legacy null mode. Any changed header becomes explicitly unresolved; unchanged evidence keeps the legacy null value.

After the correction, all 16 personal/group item-edit controls and all 31 saved-review tax-mode tests passed. The OCR acceptance catalog source hash for the changed bill screen and its canonical trusted catalog digest were refreshed. Complete clean-commit validation, retained OCR replay, fresh independent source reviews, native acceptance, hosted checks and merge gates remain separate. This correction changes mobile provisional review behavior only; it does not alter API Apply authority, authoritative money calculations, fixture expectations, OCR model bytes, schema, auth, deployment or live network settings.
