# Current Android image-to-preview qualification candidate

Source-only candidate, no executable admission. This is a minimal supervisor of
current repository product code and its unchanged Android Flutter test command.
It imports no Northstar61-file overlay, changes no parser/preview/model/fixture
truth, and does not transfer any consumed native or cleanup packet authority.

## Scope and bindings

Current all101 immutable image-to-preview integration tests and their existing
additional native controls run unchanged. No single-case flag or weaker score is
introduced. Native results and strict fixture quality remain distinct from setup,
process exit and cleanup. nativeReady is always false here: independent acceptance
collection and exact-head tests/reviews/CI remain separate downstream gates.

A new packet binds current clean Git head, a frozen tracked-source tar archive,
all six tool executables, the actual Android system image hash, exact model/fixture
input bytes, this supervisor, existing disposable_lifecycle.py, unchanged
bounded-process-capture.mjs, independent exact five-file capsule/review receipts,
protected source/history pins, five qualification locks and one managed execution
job. Atlas independently authenticates actual model/tool launch history and admits
the exact packet; ordinary executor approval remains mandatory. An audit reference,
file hash, JSON boolean or invocation object is not platform permission.

No current checkout, old overlay, consumed directory or saved diagnostic is edited
or deleted by the runner. The source archive is extracted into a fresh private
scratch tree, refusing symlinks, special files, traversal and duplicate members.
Model/fixture copies are hash-checked. Pub resolution is offline and may not change
the pinned lockfile. Builds write generated files only in that isolated source.
Normal pinned Flutter startup necessarily writes cache engine stamps/realm/lock;
Flutter Gradle plugin build state and offline Pub cache may also be written.
These exact scopes are declared by the packet and checked, never hidden behind an
SDK-copy/alternate mount/read-only claim. The warm tool snapshot/key must remain
present; tool rebuild/upgrade/download is not admitted. Any actual platform denial
is terminal, never bypassed via another SDK, credentials, access or mount.

## Admission and owned lifecycle

Before any SDK launch: exact network/protection observations must equal the
user-authorized Boston dedicated policy (including exact IP/server), maintenance
hold must be false with no mutation, only this registered job may be active and no
queued work may exist. Require clean source/head and all pinned inputs, current
boot identity, KVM API12, RAM>=12GiB/disk>=50GiB, all five distinct inode/FLOCK leases,
no other known native candidate or occupied5037/5554/5555 socket. Related ancestry
is inspected using basic metadata only. Unrelated protected helper executable/cwd
metadata remains unrequested; no whole-host atomic/future-manual-client exclusion
claim is made. Observe the current thread's SIGTERM unblocked/not ignored before
each child; never change masks/dispositions to pass a gate.

The existing lifecycle helper creates the private unique run once. Durable
CONSUMED and launch-attempt records precede SDK/client launches. An uncertain
record/Popen return is not retried. All preparation SDK commands are direct owned
Popen children with original pidfds/start identities, including pub and AVD creation;
timeout does not use subprocess.run's implicit native SIGKILL or hide Java children.
Command count<=1024. The AVD, HOME, Android-user, Gradle writable home and temporary
directories are private scratch; host AVDs/keys and VPN/security settings unchanged.

Start exactly one foreground owned ADB and one headless no-snapshot API35 emulator.
A client is forbidden unless the original foreground server and its loopback5037
listener remain proved. Explicit -H127.0.0.1/-P5037 and numeric ADB_SERVER_SOCKET
avoid the implicit localhost-server-start path; no deliberate replacement server,
kill-server, emu-kill, group sweep or global ADB operation is issued. Upstream AOSP
client and socket-source references below motivate the numeric remote-style
connection; exact tool binaries remain privately pinned and source-reviewed.
There remains a bounded ownership-check-to-connect race, not atomic whole-host
exclusion. A different/missing server or actual competing native work blocks.

Only the new emulator-5554 receives boot-readiness checks and airplane/wifi/mobile
isolation commands, once each for writes, with readback. These change the private
disposable emulator, not host networking. No OCR runner starts without observed
isolation. Device-side network-denial assertions remain unchanged in the real test.

The old Node capture helper remains unchanged as command-contract reference but
is not executed here: its numeric process-group cancellation is outside this
qualification path. The supervisor starts Flutter directly with the same current
Android test argv, retains its original pidfd, and hard-caps each output stream
at32MiB using bounded pipe drainers. Overflow is counted, persisted as truncated
process output and always fails the epoch. For SDK/native children the supervisor
signals only its own still-live direct original pidfds, at most one SIGTERM each:
Flutter runner, emulator root, foreground ADB, and any unfinished preparation/client
commands. No supervisor SIGKILL, host/group/session signal, fallback or retry.
An uncertain identity/syscall blocks; no PID substitution. Normal child wait status
is recorded because these are actual direct children, unlike historical orphans.

## Bounds, retained evidence and failure

Fixed phases: preparation300s, emulator boot600s, current full native test10800s
(existing CI180minute bound), cleanup90s. Each direct owned cleanup wait<=20s,
constrained by remaining cleanup allowance. Observations, log-size checks and
maintenance/Boston/known-work gates run during the native wait. Uninterruptible
kernel/filesystem calls and scheduler delay cannot be made atomically bounded;
no later effect is authorized after the next deadline check. Zero native retries.
ADB/emulator/command logs above4MiB fail into cleanup; original scratch is retained.

Cleanup is always attempted on failure. If own processes or related sessions remain,
a new native candidate appears, active qualification sockets remain (kernel-only
TIME_WAIT without an inode is excluded), or evidence/release fails, report failure
and retain the unresolved managed epoch for coordination. Never claim clean because
an intermediate wrapper disappeared. No-child precheck failure performs no cleanup
effects. A previously existing run is never recaptured or modified.

The existing lifecycle captures bounded diagnostic prefixes and completeness flags,
then a single-use terminal record with actual test status, cleanup proof and false
native readiness. All private per-command logs stay in scratch even when only
allowlisted summaries/prefixes are retained. Never delete source/logs or pretend
truncation is complete evidence. Failed test exit propagates as a nonzero normal
executor status; normal executor return and actual postflight/registry settlement
must be independently read back before declaring this epoch complete.

## Observer and policy trust boundaries

The fixed status-only NordVPN and installed maintenance-status observer commands
use ordinary subprocess timeouts, which may SIGKILL and reap their own transient
read-only client process. Git read-only metadata commands are also control-plane
observers. They do not signal a daemon, change registry/settings, launch a native
SDK child or authorize broader process control. The no-supervisor-SIGKILL claim
applies to the separately recorded SDK/native process set, not these existing
read-only timeout mechanics. A timeout fails the gate and stops native progress.

Private Server/IP are mandatory exact values in the independently admitted raw
packet and runtime observations must equal every policy field. Generic source
constrains Boston/US/NordLynx/enabled protections, but cannot authenticate or grant
a new owner endpoint. Atlas must verify the exact private endpoint before
admission. Changing it changes the admitted packet SHA; there is no arbitrary-US
or packet-self-approved runtime bypass. Private addresses are never in this
external reviewer capsule.

ADB server listen uses upstream's canonical tcp:localhost:5037 form; the explicit
pre-emulator gate proves its IPv4 127.0.0.1:5037 inode is owned by the original
foreground child. If an implementation instead listens elsewhere or fails, no
emulator or client command launches. Client -H127.0.0.1 and numeric environment
are intentionally distinct from the supported server listen form. This does not
claim an observed binary run before admission.

Preparation hash/copy/extraction steps check the shared phase clock between
bounded chunks/members and after long work. Native launch has its own adjacent
clock check after durable intent; no skipped check permits SDK work after expiry.
A post-CONSUMED setup failure with zero children still requires fresh native/port
census before any cleanupVerified=true record; pre-CONSUMED rejection creates no
cleanup effects or historical-record writes.

## Revision3 descendant ownership and adjacent client gate

The Linux supervisor becomes a child subreaper before any SDK child is launched.
This is a property of this new process only, not a host service/access setting or
signal-mask change. Detached/double-forked descendants are adopted back to it
instead of escaping to PID1. Basic positive ancestry/adoption identities are
retained even for arbitrary names and separate sessions. Cleanup reaps only its
non-Popen adopted direct children, preserving actual Popen wait statuses. Any live
adopted or previously observed owned descendant blocks cleanup success; it is
never added to the signal set. Unknown related helpers are observed, not killed.

ADB client launch repeats original-server/listener proof after all observers and
durable launch intent, directly before Popen and its final clock check. A finite
check cannot prevent scheduler/manual races; none is claimed atomic.

All original tracked Git source bytes/modes are rechecked after offline Pub
preparation and the real test, while normal extra generated files are permitted
only after the initial exact archive inventory check. Terminal and diagnostics
directory entries receive a final supervisor fsync; that receipt still does not
assert normal executor return, which requires actual external tool readback.

Revision4 also requires the adjacent owned-server check for emulator and Flutter
launches, not only ADB clients. Every preparation model/source/lockfile hash uses
the phase clock; read-only Git observers have explicit five-second timeouts plus
pre/post phase checks. A consumed zero-root failure cannot declare clean while
an adopted child remains. These are bounded observer checks, not permission to
change signal masks or kill an unrelated host process.

Revision4 additionally checks free-space margin on every declared shared SDK/Pub
write filesystem, not merely the run volume. The image pin must name the exact
API35 SDK package system.img; both -sysdir and -system explicitly pass that same
image to the new emulator, and tool package roots must agree. Actual direct test
exit status is retained even if a later source/evidence check fails; the separate
qualification failure and nonzero executor return prevent a false success.

After owned cleanup, all protected source/history pins and original source
archive, actual system image and model inputs are rehashed before success.
The owned ADB listener check tolerates a disappearing unrelated transient
client FD while still requiring the exact original listener inode; it never
accepts an unowned or differently bound listener.

Revision5 places durable CONSUMED before the process-local subreaper change, so
a prctl failure is a consumed failed operation with zero SDK children. A failed

uncertain durability truthfully, and cannot change subreaper state or launch a
